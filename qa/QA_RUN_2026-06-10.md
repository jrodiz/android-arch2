**Phase 0 notes (environment, not app defects):**
1. *Gradle config-cache corruption*: first baseline run failed at configure with `InjectMappingFileIdTask not found` (Crashlytics plugin classloader). Fixed by `--stop` + deleting `.gradle/configuration-cache`. No code change.
2. *emulator-5554 saga*: original `Medium_Phone` AVD hangs indefinitely at "Enabling Vulkan" when launched as the second concurrent instance (crashpad minidumps each attempt; wipe-data didn't help). A SIGTERM-immune zombie qemu then held the port-5554 instance lock, making every retry fail with "Another emulator instance is running" (only visible once Vulkan was disabled, because the lock check runs after GPU init). Resolution: `kill -9` the zombie, removed stale `multiinstance.lock`, switched to `api35_pixel` AVD launched with `-feature -Vulkan,-GLDirectMem -gpu swiftshader_indirect`. Boots and renders the app correctly. **Re-use this exact launch recipe for 5554 for the rest of the run.**

**Phase 2 notes:**
1. **Emulator GPS HAL is broken on the `api35_pixel` (swiftshader) AVD.** `adb emu geo fix` / authed telnet `geo fix` both return OK but inject nothing — `dumpsys location` stays frozen at the boot default (Mountain View, et=+6m). The deck reads the **stored** `owners/{uid}.location` GeoPoint (not live GPS — `FirestoreDeckRepository`), so the env workaround is to PATCH iris's owner location to Manhattan via Firestore REST (location `40.7484,-73.9857`, geohash `dr5ru6`, matching the seeded cluster near lena). The deck flow itself is tested faithfully. **diego needs the same REST patch before Phase 4.** The location-capture pipeline (GPS→owner doc) was already exercised in onboarding; only the injection is broken.
2. **D-004 detail-path cluster deferred to Phase 4 (with D-pre2).** DECK-08 (pass from detail doesn't advance the deck) and DECK-09 (no-pet like from detail shows no RequiresPet dialog) both stem from `DeckPetDetailViewModel.swipe()` discarding the `SwipeResult` + the deck not being reactive to swipe writes — the same family as the already-deferred **D-pre2** (detail like → no celebration). These share the `DeckPetDetailViewModel` + deck-route plumbing and are best fixed once, holistically, in Phase 4 where matches exist to test the full detail→deck→match→celebration→advance flow end-to-end. No data is lost (server writes are correct). **Decision pending user confirmation at the Phase 2 pause** (fix-now vs. batch with D-pre2).
3. **adb cannot drive Compose swipe-to-dismiss gestures** (DECK-04, UX-02). The card's `awaitTouchSlopOrCancellation` + custom `horizontalDrag` (DeckCardView.kt) ignores synthetic `input swipe`/`input motionevent` (verified: the card never offsets even mid-drag). The swipe logic is code-verified and the button Pass/Like paths cover the same outcomes. Real devices/touch are unaffected.
4. **Species filter chips reflow when toggled** — batch taps using pre-toggle coordinates miss; must re-dump between each chip tap (analogous to the Phase-1 sign-up form). Species filter itself works correctly.
